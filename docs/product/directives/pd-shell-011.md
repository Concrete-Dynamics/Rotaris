### PD-SHELL-011 — a keyboard user moves between the main window's regions on F6 and Shift+F6

The one vocabulary of named actions REQ-SHELL-048 defines MUST include two commands, "Focus next region" on F6 and "Focus previous region" on Shift+F6, presented on every surface that vocabulary reaches and bound beside the shortcuts REQ-SHELL-049's table names, as if listed there; the table's text is not edited. Each press MUST move keyboard focus to the next or the previous region of the main window, in the order REQ-SHELL-024 lays the window out and wrapping from the last region to the first and back:

- the title bar;
- the persistent-notice banner;
- the navigation rail;
- each pane of the showing primary view that is on screen, in that view's own reading order — in the Workspace view the context sidebar, the centre panel with the transcript, the composer and the inspector, where an open overlay drawer stands in for the pane it carries;
- the status strip.

A region that holds no focusable element at that moment — a closed overlay drawer, an empty banner slot, a strip showing no link (REQ-SHELL-039) — MUST be skipped. Focus MUST land on the element that last held focus in that region during the window's life, otherwise on the region's first focusable element, with its focus ring drawn as REQ-SHELL-148 requires. The commands move focus and nothing else: they MUST NOT switch a view, check a rail button, change any selection, open or close an overlay drawer, or submit anything. While a modal surface is open neither chord SHALL have any effect. Invoked from the command palette, the command moves from the region that held focus before the palette opened; invoked from the composer's slash catalogue, from the composer's region. A host that has already claimed either chord is answered by REQ-SHELL-165, unchanged. REQ-SHELL-028 and REQ-SHELL-032 are unchanged: each rail button stays its own Tab stop and the rail stays arrow-inert. REQ-SHELL-062 is unchanged, and no command opens or closes an overlay drawer.

**Why, and what it costs.** REQ-SHELL-049 is the authoritative shortcut table and binds nothing that moves between the window's regions, so a keyboard operator leaving the composer for the inspector, or the transcript for the rail, Tabs through every stop between them; Ctrl+L reaches only the composer and Ctrl+F only the search panel. The table is exhaustive, so the pair cannot be read into it and enters here, extending REQ-SHELL-048 and REQ-SHELL-049 and displacing nothing; the labels follow the shape of the table's own, "Focus run prompt", and name the commands this directive mints. The region order is REQ-SHELL-024's vertical layout and no new structure; the title bar is a region because it holds the workspace chip (REQ-SHELL-035) and the window controls (PD-SHELL-003). No drawer command is minted: a drawer exists only in compact mode (REQ-SHELL-062), where its toggles, REQ-SHELL-055's Escape and REQ-SHELL-063's agent selection already open and close it and an open one is one press away, so a third route answers no harm the record names; were one minted later, OQ-509's reading of REQ-SHELL-048 would have it listed disabled with its reason outside compact mode (REQ-SHELL-060), not omitted. The rail's seven Tab stops stand because REQ-SHELL-028 refuses arrow traversal on purpose and a single roving stop would need it. The cost is two more entries on every surface of the vocabulary, two more lines in keyboard help, a defined region list per primary view and the last-focused element remembered per region; the gain is that any region of the window is reached in at most a handful of presses from any other, with no view switched and no selection moved on the way. Where a supported desktop claims F6, REQ-SHELL-165 governs and the palette entry remains; macOS is unmeasured (IC-3) and is [OQ-505](../../archive/architecture/open-questions/70-spikes-and-later-questions-37.md#oq-505)'s to reopen through OQ-504's route.
