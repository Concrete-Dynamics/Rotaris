### PD-TOOLS-021 — the approval dialog states what a session approval lets through

The approval dialog of REQ-TOOLS-063 MUST show, after the fine-print line `Matched rule: <rule_id>` and its reason and before any queue count, exactly one scope line stating what "Approve for this session" would admit. The line is chosen by the match the session rule would make under REQ-TOOLS-024 as narrowed by PD-TOOLS-004, and it MUST be produced by the same matching that mints the rule, never derived from the detail box or the argument summary:

- **A call with a command facet:** `Approve for this session also allows the <persona> persona to run this exact command, without asking, until the session ends. Changing the permission mode or the policy does not withdraw it.`
- **A call to the public `write_file` or `haet_edit` whose path arguments resolve (PD-TOOLS-004):** `Approve for this session also allows the <persona> persona every later <tool> call on <paths>, whatever it writes, without asking, until the session ends. Changing the permission mode or the policy does not withdraw it.` — `<paths>` is the resolved path set, sorted and comma-separated, each path written relative to the workspace root when it lies inside it and absolute otherwise.
- **Such a call carrying a path that cannot be resolved:** `Approve for this session covers no later call, because a path in this call could not be resolved; it allows this call only.`
- **Every other call:** `Approve for this session also allows the <persona> persona to call <tool> with exactly these arguments, without asking, until the session ends. Changing the permission mode or the policy does not withdraw it.`

To carry it, the approval payload of REQ-TOOLS-056 MUST carry a further field, `session_scope`, holding the case (`command`, `paths`, `unresolved` or `arguments`) and, for `paths`, the resolved path set, computed where the request is raised; a host renders the line from that field, `persona` and `tool_name`. The line MUST be the accessible description of the "Approve for this session" button. The line MUST NOT state whether the call can be undone. The headline, the requester line, the detail box, the fine-print line, the queue count, the three buttons with their labels and styling, and every other string REQ-TOOLS-063 fixes are unchanged.

**Why, and what it costs.** REQ-TOOLS-063 labels "Approve for this session" and says nothing of what the grant then admits, and the grant is wider than the call on screen: REQ-TOOLS-024 matches every later identical call from that persona, and PD-TOOLS-004 widens a file write's grant to every later write of the same path set, overwrites included, which that directive records as what is given up. The dialog is the only place the grant is made, and under REQ-TOOLS-063's own reasoning (no keystroke approves a call that has not been read) the operator is owed the scope before the press, not after. The scope is a fact the policy already holds, so stating it invents no behaviour; it is computed where the request is raised because the renderer holds neither the resolved path set nor whether the named tool is the public one (PD-TOOLS-004's first execution), and a line worded from the redacted, clipped argument summary could understate the grant. What it costs: one more line on a dense dialog, read once against a grant misunderstood for the rest of the session; a payload field added through the channel and contracts path, extending REQ-TOOLS-056's enumeration; the fit at 560×380 (REQ-SHELL-022), which the build measures; and upkeep, since the four strings restate the matcher and must follow any change to REQ-TOOLS-024 or PD-TOOLS-004. Undoability is left out because no single recorded fact covers every tool (REQ-TOOLS-132 keeps ten undos per path for the file tools; nothing holds one for `terminal`, `fetch`, a git tool or an MCP tool), so it stays a request. Nothing is displaced: PD-ORCH-005 narrows REQ-TOOLS-063 on the quit and is untouched. The strings are fixed here, so under §1.11 the copy voice does not govern them. Raised by [OQ-519](../../archive/architecture/open-questions/70-spikes-and-later-questions-37-continued-3.md#oq-519).
