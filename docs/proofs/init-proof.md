# `init-proof`

What this proof measures and re-verifies. The [proof registry](README.md) carries its area, prerequisites,
platforms, flags and neighbours; the script is [`apps/desktop/scripts/init-proof.mjs`](../../apps/desktop/scripts/init-proof.mjs).

Project initialization resolved once per workspace open (ADR-0064); scenario 3 reads the dialog **before** its Escape (the reading marks the document and the key waits for the mark), and since 2026-10-02 that no title-bar or notice-slot button has the dialog at its centre, photographing it (`consent-dialog.png`, OQ-187), and asserts that the background task starts and completes beside the consent prompt. Scenario 4's background banner must name its project, the folder's name after the headline and the folder at the head of its detail (PD-WORKSPACE-005, OQ-171). Before the repairs it failed on Linux in both orders: a skip landing ahead of the resolution swallowed the background task (`docs/defects/fixed/a-skip-answered-before-the-open-resolves-swallows-the-background-task.md`), and the background run drew itself in the dialog, which then refused Escape when the resolution came first (`docs/defects/fixed/the-setup-dialog-takes-a-background-run-as-its-own.md`). It needs the bundled code-intelligence runtime: it builds it when it builds, and with `--skip-build` refuses before any launch naming `pnpm code-intel:bundle`; a setup that fails anyway is quoted from the app log (`docs/defects/fixed/init-proof-reads-a-missing-code-intelligence-bundle-as-a-task-that-recorded-nothing.md`)
