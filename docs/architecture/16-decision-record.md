# 16 — Decision Record

> Perspective: Key architectural decisions with rationale and alternatives.
> Diagram type: Table

---

| #           | Decision                                                                               | Rationale                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Alternatives Considered                                                                                                                                                            |
| ----------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ADR-001** | Single-process asyncio (no daemon / server)                                            | Simplest deployment story — `pip install` and run. No port management, no IPC.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Separate orchestrator daemon; message queue (Redis/NATS)                                                                                                                           |
| **ADR-002** | `LocalConversation.run()` in `asyncio.to_thread()`                                     | OpenHands SDK `run()` is synchronous; off-loading keeps the event loop free for TUI responsiveness and concurrent child scheduling.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Re-implementing SDK as async; blocking the event loop                                                                                                                              |
| **ADR-003** | `ChildManager` uses `threading.Lock`                                                   | `RotarisDelegateTool` runs inside a worker thread (`asyncio.to_thread`), not the event loop. Asyncio locks are not usable across threads.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | `asyncio.Lock` (incompatible across threads); queue-based serialization                                                                                                            |
| **ADR-004** | Config is field-wise overlay, not deep merge                                           | Predictable semantics — a workspace persona fully replaces the inherited persona, no partial mixins. Prevents accidental tool list accumulation across layers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Deep merge (complex, surprising behaviour for `tools:` lists)                                                                                                                      |
| **ADR-005** | `ChildReportArtifact` as parent–child hand-off                                         | Keeps parent context bounded. Parent never needs to read the child's full transcript. Structured fields (edited_files, errors, next actions) are more useful than raw text.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Parent reads raw child transcript; shared memory / event bus                                                                                                                       |
| **ADR-006** | HAET is opt-in; built-ins use `FileToolEngine`                                         | Most agents work fine with fuzzy-fallback file editing. HAET's hash anchoring adds value only on large files where line identity is ambiguous. Opt-in avoids config complexity for common cases.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | HAET as default; no alternative editor                                                                                                                                             |
| **ADR-007** | `create_agent_for_persona()` returns a factory                                         | The `delegate` tool needs to spawn children without JSON serialization of complex deps (`child_manager`, `scheduler`). A closure-captured factory satisfies this cleanly.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Injecting deps via global state; serializing to JSON                                                                                                                               |
| **ADR-008** | Atomic writes everywhere (`mkstemp + os.replace`)                                      | Crash safety — no partial-write state. Session snapshots, OAuth tokens, HAET edits, secrets, and display config all follow this rule.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Direct `open().write()` (unsafe on crash)                                                                                                                                          |
| **ADR-009** | `SecretStr` for all `api_key` fields                                                   | Structural redaction — keys never appear in `model_dump()`, logs, or report artifacts. Safer than string-scanning.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Manual redaction in log formatters                                                                                                                                                 |
| **ADR-010** | MCP server unavailability is non-fatal                                                 | Agents should degrade gracefully when optional tool servers are unreachable. A hard failure on missing MCP server would break runs for users who don't have every server configured.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Hard failure on missing MCP server; required vs. optional server distinction                                                                                                       |
| **ADR-011** | Sequential top-level Ralph loop                                                        | Simplicity and debuggability. The loop runs one top-level todo task per iteration. Parallelism is opt-in via the `delegate` tool and the scheduler within that iteration, not forced across independent todo phases.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Parallel top-level iterations; pipeline scheduling                                                                                                                                 |
| **ADR-012** | Workspace path containment enforced in tools                                           | Prevents agents from reading/writing outside the project directory without explicit user opt-in. Security boundary between tool invocation and host filesystem.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Trust all paths; sandbox via OS permissions                                                                                                                                        |
| **ADR-013** | Progressive truncation of old tool results                                             | As conversation history grows past 75% of the model context window, older tool-role messages are truncated more aggressively than newer ones. This preserves recent working context while letting ancient file reads fade out smoothly. The context window is resolved from the known-model registry in `providers/limits.py`. Age-weighted linear curve: 0% truncation at 75% usage, oldest → 85% truncated at 100% usage, newest → 15% truncated. Also wraps `RuntimeError("No active exception to reraise")` with a single retry to handle a non-deterministic thread-boundary bare-raise in the SDK.                                                                                                                                                                                                                                                                                                                                                      | All-or-nothing condensation (loses nuance everywhere); fixed window (discards old context even when budget available); no truncation at all (hits context limit hard)              |
| **ADR-014** | Split session state plus evidence files                                                | Long-running sessions need resumability without unbounded monolithic snapshots. `state/resume.json` keeps resumable state, `state/ui_transcript.json` keeps UI transcript, and `evidence/` stores diagnostics; `snapshot.json` remains as a compatibility copy for older tooling.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Keep a single ever-growing snapshot; move to an external database                                                                                                                  |
| **ADR-015** | Skip summary agent when child published an authored artifact                           | When a child produces an `agent_published` artifact during its run (`artifact_write`), the scheduler detects it in `_get_latest_authored_artifact()` and builds the `ChildReportArtifact` directly from the artifact body, bypassing the `SummaryAgent` entirely. This saves one LLM call per child and preserves the child's original structured output (plans, research, code changes) as the canonical response without paraphrasing through a second model. The `SUMMARIZING` state is also skipped, so the TUI never shows the stale "Summarizing response" cue for artifact-backed children. The `SummaryAgent` remains as a fallback for children that did not publish their own artifact.                                                                                                                                                                                                                                                             | Always invoke the summary agent (wastes tokens on already-structured output); require an explicit persona-level toggle to enable skipping                                          |
| **ADR-016** | Per-model delegation queue instead of hard rejection                                   | When a delegation targets a model whose `max_parallel` cap is reached (e.g. 3/3 active on `deepseek/deepseek-v4-pro`), the `RotarisDelegateExecutor` enqueues the child into a `WAITING_ON_MODEL_SLOT` state rather than returning a rejection error to the parent agent. The child waits until a sibling on the same model terminates and releases a slot. Only `RUNNING`/`SUMMARIZING` children count toward `max_parallel` — `WAITING_ON_MODEL_SLOT` children do not consume an LLM connection. A `_release_model_slot_locked()` call in `mark_child_terminal` dequeues the next queued child and transitions it to `QUEUED`, where the scheduler's next drain cycle picks it up. This is more agent-friendly: parallel delegate calls succeed silently, and the parent keeps working while slots free up.                                                                                                                                                  | Hard rejection (parent must retry manually); unbounded concurrency (risks governor-rate 401s); blocking the parent until a slot frees                                              |
| **ADR-017** | Tool args/results captured only on error (not all calls)                               | `tool-calls.jsonl` stores the tool arguments and result **only** when the tool call ended with an error status (`error`, `failed`, `rejected`). Successful calls carry no payload — just `agent_name`, `tool_name`, `call_id`, `status`, `elapsed_ms`. This keeps the file small for normal runs while giving investigators the full context for every failure. An exception is made independently for stall/timeout diagnostics: the last 5 completed tool calls are tracked in memory and emitted in the issue metadata regardless of success or failure.                                                                                                                                                                                                                                                                                                                                                                                                   | Always capture args/result (file grows unboundedly on long-running sessions); never capture (blind diagnosis on failures)                                                          |
| **ADR-018** | System prompt text resolved and snapshotted in `run_config.json`                       | The persona `system_prompt_file` references are resolved at session-start time via `load_system_prompt()` and the resulting text is stored as `resolved_system_prompt` in `state/run_config.json`. This ensures the actual prompt text used at runtime is captured in the session evidence regardless of whether the prompt file changes between runs. Only file-backed prompts are resolved — inline `system_prompt` config values are already present in `config_snapshot`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Resolve on first agent creation (may never be relevant if the persona is never used); leave the snapshot as a file path only (cannot diagnose prompt-related issues retroactively) |
| **ADR-019** | Debug log level is configurable via `runtime.session_log_level`                        | The per-session evidence/debug.log file respects a `runtime.session_log_level` setting (default: `"WARNING"`). Users can raise it to `"INFO"` or `"DEBUG"` during development to see richer conversation lifecycle events (tool call arguments, conversation state transitions, pause diagnostics) without changing code or re-installing. The setting applies only to the file handler, not to console output.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Hard-code `WARNING` (must re-deploy to get more detail); make console output configurable too (risks leaking to stdout in production use)                                          |
| **ADR-020** | Completion classification via small-model LLM replaces keyword-based report validation | The `_validate_child_report` keyword heuristics (checking `errors`, `next_recommended_actions`, summary text for contradiction markers) and the `IntentValidator` LLM check were both replaced by a single `CompletionClassifier` (`ralph/completion_classifier.py`) that uses the `small_model` config alias. The classifier makes one cheap LLM call per iteration and returns a structured verdict: COMPLETE, NEEDS_ITERATION, or UNCLEAR. UNCLEAR is always treated as COMPLETE so transient LLM failures never block the run. Keyword heuristics were brittle — phrases like "continue by rebuilding" triggered false-positive downgrades that caused infinite loops (session 9303805c4643). A same-task loop detection guard (max 3 consecutive PENDING on the same task → ABANDONED) provides an additional safety net. Config gating moved from `RuntimePolicy.validate_intent` (deprecated) to `RuntimePolicy.classify_completion` (default `true`). | Always use keyword heuristics (false positives, brittle); use the orchestrator's main model for the check (wastes expensive tokens); hard-fail on error (blocks the run).          |
| **ADR-022** | Prompt behaviour composed from a persona x intent x tier matrix                       | Run-varying agent behaviour (autonomy, research policy, task sizing, verification ownership, artifact duties, report shape, fan-out budget) lives in exactly one place: `agents/prompts/playbooks/`, resolved by `agents/playbook.py` and injected at `[[ROTARIS:PLAYBOOK]]`. Previously it was spread across 13 intent snippet files (orchestrator-only), five hardcoded section builders in `prompt_render.py`, and prose in each persona prompt — which drifted and contradicted itself (a `small_model` agent told to be strict while its model-family block told it to "make autonomous decisions"). The orchestrator keys on the *implementation owner's* tier, not its own, so the same intent routes differently by delegate capacity. `BUDGET` also clamps the real `RuntimePolicy`, so a budget the model ignores still binds. | Per-intent snippet files only (no tier axis); hardcoded Python dicts (not workspace-overridable); a full rules engine (over-built for 8 slots) |
