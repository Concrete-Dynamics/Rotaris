## 15. The interface

| I-03 | An off-screen surface performs **zero repaints and runs zero repaint or refresh timers**, yet its first painted frame on becoming visible already carries current state, within the 100 ms budget. | HARD | REQ-SHELL-076, REQ-SHELL-084, REQ-SHELL-151, REQ-CHAT-063, REQ-WORKSPACE-150 |
| I-04 | Paint and measure cost depends on **visible and changed rows, never on total rows**; bounded residency — **5000 resident rows**, `REQ-SESSION-192` being the product's single definition of residency and `REQ-CHAT-165` holding no copy of the cap — with on-demand paging **off the interface thread**; a re-loaded row is identical to the row released. **The binding figure is not the residency bound but U-04's comparison**: an update at 10,000 recorded rows costs no more than **twice** the same update to an **empty** session, p95, run to surface. A re-projection that is constant in the resident window is still not within a factor of two of nothing, so constancy alone does not discharge it. | HARD | REQ-CHAT-055, REQ-CHAT-154, REQ-CHAT-157, REQ-CHAT-165, REQ-MONITOR-222, REQ-MONITOR-223, REQ-SESSION-160, REQ-SESSION-192 |

| I-06 | Expansion state is keyed by **stable identity, not position**; scroll preservation is **by anchor, never by stored pixel offset**. | HARD | REQ-CHAT-053, REQ-CHAT-059, REQ-CHAT-071 |

| I-08 | The row model retains **untruncated** tool input and output; display caps affect only what is drawn and take effect immediately on rows already on screen. | HARD | REQ-CHAT-046, REQ-CHAT-061, REQ-CHAT-166, REQ-CONFIG-472 |
| I-09 | Markdown rendering is **synchronous**, issues **no network request**, renders mid-stream incomplete input without error, and selection must select exactly the characters covered **in every row category**. | HARD | REQ-CHAT-056, REQ-CHAT-075, REQ-CHAT-076, REQ-NOTIFY-243 |
| I-10 | **The count of live paintable visual elements must be invariant after window construction**, across six later phases; the second structural count is explicitly informational and no invariant reads it. **What counts as the first is disputed, `REQ-UIBENCH-050` and `REQ-UIBENCH-054` are unamended, and the dispute is now settled empirically rather than argued.** `REQ-UIBENCH-050` still defines `widgets` by an observable test — elements "that occupy space in the window's layout and can be painted" — and still says both counts are "defined against the interface framework the product is built on", in the same paragraph; `resolutions/21` rows 29 and 13 press the framework-neutral reading. **Measured against a running window: under reading 1 the count was 629 at all 384 observations** — 84 phase records across twelve runs, 130 intra-phase probes, 110 tail-loop samples and 60 resize steps, two scroll variants, onscreen and offscreen — **and under reading 2 it moves 630 → 777 or 630 → 715 at the first post-construction record, in every run**, by +147 or +85, before any of the phases OQ-28 discusses and by an amount padding cannot repair. Under reading 2 the count also becomes a property of where the reader is scrolled (777 at the top, 668 at the bottom, 747 at minimum size). **The conflict is real in a running window, not only on paper — and it no longer blocks ADR-0045**, because ESC-13 is ruled: accessibility wins, the canvas is refused outright, and `REQ-UIBENCH-054` is relaxed if the framework-neutral reading is the operative one. ***The closing claim of this row is withdrawn and must not be cited (2026-09-02).*** It read: "The specification therefore currently states an invariant its own definition breaks on one live reading, and `resolutions/21` withholds the drafted relaxation. That is a specification-side action." **Both requirements have since been amended and neither statement is true.** `REQ-UIBENCH-050` now states in bold that the framework-neutral counting rule **is the operative one** — reading 2 wins — spells out that a rendered paragraph, code block or list item inside a transcript row **is** a widget, and closes the escape route by saying the framework clause "does not license a product to count only the elements its own layout declares and to leave out what it drew". `REQ-UIBENCH-054` carries ESC-13's relaxation and states its ground exactly: the invariant is withdrawn as **unsatisfiable by any admissible implementation**, not merely as unmet, because the only structure that could hold it is a canvas and a canvas forfeits `REQ-CHAT-075`, `REQ-CHAT-077`, `REQ-CHAT-065` and `REQ-SHELL-144`. The relaxation is carried by a `widgets_samples` field at the eleven indices the tail phase already samples, because a comparison between phase records alone would have deleted the no-accumulation guarantee rather than relaxed it, and `REQ-UIBENCH-085` is rewritten to report the relaxed rule. **OQ-28 is closed.** *The cost ESC-13 accepted is unchanged and is not softened by the closure: the product ships a benchmark whose headline structural invariant is gone, in a domain whose whole point is determinism — informational either way under `REQ-UIBENCH-088`.* | HARD | REQ-UIBENCH-050, REQ-UIBENCH-054, REQ-UIBENCH-085, REQ-UIBENCH-088, REQ-UIBENCH-109; `resolutions/21` rows 13, 29; `spikes/renderer-invariance-and-benchmark-cadence.md` §3.1–3.3; ESC-13 |
| I-11 | The view must own an **explicit apply/diff stage** producing six cumulative counters classified against the currently displayed state, **byte-identical across iterations in fresh processes**; `refused` and `noop` are distinguished by **validity, not by visible change**. | HARD | REQ-UIBENCH-064, REQ-UIBENCH-083, REQ-UIBENCH-099 |
| I-12 | Every iteration renders **offscreen**, in a **fresh child process** with the environment stripped and overridden, using **bundled fonts and theme with no host fallback**, and **the user's real stored settings must hold the same bytes afterwards**. | HARD | REQ-UIBENCH-037 – REQ-UIBENCH-039, REQ-UIBENCH-046, REQ-UIBENCH-047, REQ-UIBENCH-112 |
| I-13 | Phase timings close when **the interface has finished showing that work's effect**, bounded at 30 s — so the architecture must expose that signal. **Three properties of that signal are now forced rather than optional, and two of them by measurement.** It must resolve **whether or not the change it applied is inside the viewport**: a transcript legitimately changes rows the reader cannot see, and a signal that fires only on visible damage converts "nothing to paint" into "the interface never finished" — measured, the offscreen paint event delivers 59.4 frames/s where there is damage and about one frame per five seconds where there is none, and 3 of 7 phase records timed out on exactly the phases with no visible damage, one phase running 360.4 s of which 360 s was expired bounds. It must not be **forced**: `invalidate()` produces a paint in 0.2 ms and that paint **carries the previous frame**, 0 of 40 trials correct, returning `settle_timed_out` false — a worse failure than the timeout, because nothing in the record marks the figure as wrong. And the signal must be **the same in both modes**, since a benchmark-only rendering path is forbidden. `REQ-UIBENCH-051` and `REQ-UIBENCH-119` fix an outcome and a bound and name no signal, event or API, so the choice is ADR-0053's; it is now a renderer double `requestAnimationFrame`, which resolved in 2.6–30.9 ms with no timeout anywhere. **That is a proxy and the record says so**: it establishes that a frame boundary passed after commit, not that a frame containing the change was presented, and nothing establishes that the two measure the same interval where both resolve. | HARD | REQ-UIBENCH-051, REQ-UIBENCH-119, REQ-UIBENCH-027, REQ-UIBENCH-112; `spikes/renderer-invariance-and-benchmark-cadence.md` §7 |
| I-14 | Responsiveness is measured by a probe every 10 ms, never accumulated, with the whole measured part covered by exactly one record's interval and one absolute threshold applied. | HARD | REQ-UIBENCH-049, REQ-UIBENCH-118 |
| I-15 | The preference store has a **closed key table** — a key not in it does not exist — is established **before the first preference read**, is disjoint from the configuration surface in both directions, and must be **redirectable per process on every platform**. Its physical path and encoding are **free**. | HARD (properties); FREE (form) | REQ-SHELL-006, REQ-CONFIG-405, REQ-CONFIG-463, REQ-GIT-153, REQ-UIBENCH-038, REQ-UIBENCH-039 |
| I-16 | The theme choice is committed **at the moment it is made**; reading a theme preference never writes it back; an unknown name degrades silently and the stored value is left as the user left it. | HARD | REQ-SHELL-009, REQ-SHELL-128, REQ-SHELL-131 |
| I-17 | **Two different draft debounces** are both normative, with four named flush points for the slower one. | HARD | REQ-CHAT-014, REQ-CHAT-015, REQ-SHELL-159, REQ-NOTIFY-066 |
| I-18 | Contrast is settled **from rendered pixels on a real display**, not from token arithmetic; derived colours are corrected by **raising perceptual lightness only**, never by darkening. | HARD | REQ-SHELL-134, REQ-SHELL-144, REQ-SHELL-145, REQ-SHELL-160 |
| I-19 | **No state by colour alone, product-wide**; **no information is available on hover alone**; every disabled control publishes its reason through both tooltip and accessible description. | HARD | REQ-SHELL-058, REQ-SHELL-149, REQ-NOTIFY-008, REQ-NOTIFY-258, REQ-CHAT-007, REQ-CHAT-027, REQ-CHAT-086 |
| I-20 | Reduced motion resolves in a fixed precedence and is **read at each animation start rather than cached**; only travel is removed, and nothing is suppressed, delayed or reordered. | HARD | REQ-SHELL-135, REQ-SHELL-136, REQ-NOTIFY-022 |
| I-21 | A theme change recolours **everything**, including engine-owned surfaces and every live window, and **cell geometry is re-measured and re-reported**. | HARD | REQ-SHELL-031, REQ-SHELL-100, REQ-SHELL-130, REQ-CHAT-058 |
| I-22 | Focus rings are drawn **wholly within the control's own bounds**, including on self-painted controls and divider handles. | HARD | REQ-SHELL-068, REQ-SHELL-148, REQ-SHELL-160 |
| I-23 | The window refuses to resize below a minimum at which **every control on every one of the seven views** is wholly inside the bounds, keyboard-reachable and fully labelled with two named exceptions; a view with no declared divider defaults opens **by equal division subject to minimums**. | HARD | REQ-SHELL-022, REQ-SHELL-047, REQ-SHELL-059, REQ-SHELL-061, REQ-SHELL-064, REQ-SHELL-065, REQ-SHELL-071 |
| I-24 | **Exactly one transient acknowledgement surface** with fixed geometry, ordering and lifetime, and **exactly one persistent notice at a time per application session** with **no queue, no restoration, no re-presentation**, publications **totally ordered**. | HARD | REQ-NOTIFY-011 – REQ-NOTIFY-027, REQ-NOTIFY-033, REQ-NOTIFY-259, REQ-SHELL-112 – REQ-SHELL-114 |

| I-31 | **New. Two of the benchmark's own invariants compose into a pass on a number known to be meaningless, and one is the only absolute threshold it applies.** `REQ-UIBENCH-119` makes `settle_timed_out` informational and says no invariant reads it, while `REQ-UIBENCH-087`'s tripwire reads `rss_second_half_growth_bytes` **unconditionally** — so a phase whose settle expires sits idle for minutes, the operating system trims the process working set, and the growth figure comes out **negative**. Measured: **−109,273,088 bytes**, which satisfies a tripwire whose threshold is +64 MiB while measuring nothing at all. Separately, `REQ-UIBENCH-118` is simultaneously "the only absolute threshold the benchmark applies" (`REQ-UIBENCH-099`) and informational like the other six (`REQ-UIBENCH-088`), which gives an implementer no guidance on what a false value should cost — and that is exactly the question the burst-versus-yielding phase driver turns on: burst measured 588–2,752 ms of event-loop lag against the 100 ms bound, yielding measured ≤74.8 ms and multiplied phase wall times by 17×–26×. Both are reported as specification defects; neither is fixed here. | CONFLICT | REQ-UIBENCH-087 vs REQ-UIBENCH-119; REQ-UIBENCH-118 vs REQ-UIBENCH-088, REQ-UIBENCH-099; `spikes/renderer-invariance-and-benchmark-cadence.md` §4, §8 |
