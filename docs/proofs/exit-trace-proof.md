# `exit-trace-proof`

What this proof measures and re-verifies. The [proof registry](README.md) carries its area, prerequisites,
platforms, flags and neighbours; the script is [`apps/desktop/scripts/exit-trace-proof.mjs`](../../apps/desktop/scripts/exit-trace-proof.mjs).

The exit trace's crash handlers in the built app (PD-MONITOR-002; since 2026-10-13, fin42, N60): an orderly launch and quit writes its quit lines and no GONE line at `error`; a second launch's run host is killed with SIGKILL from outside (its pid read from main's `hello` line) and main writes `run host exited (9)` and `CHILD PROCESS GONE (Utility rotaris-run-host: killed, exit 9)` at `error`, then its renderer is crashed with SIGSEGV and main writes `RENDERER GONE (crashed, exit 11) for <URL>` at `error`, and the application's quit (`app.quit()`) then ends the process, exit 0, through the orderly path (the dead renderer's close guard cannot answer, so it allows; since fin45, OQ-298, the quit asks no guard at all), with `quit: exiting with status 0` and `main process exiting with status 0` (since 2026-10-14, fin43: until then the quit was held for good, `docs/defects/fixed/a-main-window-whose-renderer-crashed-holds-the-applications-quit-forever.md`); since 2026-10-14 (fin44, `PD-SHELL-010`) two more launches stop the main window's renderer with SIGSTOP and end the process, exit 0, through the orderly path within 15 s with main's `warn` line naming the unanswered liveness probe — `hang` by the driver's quit and `hang-close` by the host's close (the driver's `closeWindow`, `BrowserWindow.close()`); until then both were held for good (`docs/defects/fixed/a-main-window-whose-renderer-hangs-holds-the-applications-quit.md`); since 2026-10-14 (fin45, OQ-298, `PD-SHELL-009` revision 2) the quit from outside any window asks no close guard, so `hang`'s quit exits 0 well under the probe's 5 s bound with main's OQ-298 line and no PD-SHELL-010 `warn` line (`hang-close`, a person's close, stays PD-SHELL-010's measure), and two `unsaved` launches whose renderer guard never settles — `unsaved-quit` (the driver's quit) and `unsaved-sigterm` (SIGTERM to main) — each exit 0 through `quit: exiting with status 0` with no dialog and the workspace configuration file byte-identical; `unhandledRejection` and `uncaughtException` cannot be raised in main from outside and stay unmeasured

**On Windows** (since 2026-10-20, the Windows ARM64 session's C4): Node there sends only SIGINT, SIGTERM, SIGKILL and 0,
the last three as `TerminateProcess` with exit 1, so the win32 branch expects `run host exited (1)` and `… killed, exit 1)`,
ends the renderer with `process.kill(pid)` (main writes `RENDERER GONE (killed, exit 1)`), hangs it with `NtSuspendProcess`,
and has `unsaved-sigterm` check the termination (exit 1, no quit line) in place of the orderly path. Run it on a quiet host:
under a parallel session's 100% CPU the main process was reaped more than 15 s after its last line, and the orderly control
failed on that alone ([`exit-trace-proof-expects-posix-signal-semantics-on-windows.md`](../defects/fixed/exit-trace-proof-expects-posix-signal-semantics-on-windows.md)).
