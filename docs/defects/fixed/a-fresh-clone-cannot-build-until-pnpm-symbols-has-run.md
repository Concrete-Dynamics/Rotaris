## A fresh clone cannot build until `pnpm symbols` has run

`packages/kernel/src/generated/` is git-ignored, and only `pnpm symbols` writes it: directly, as the first stage of
`pnpm check`, or through Vitest's global setup before a test collection. Every build imports it, because
`packages/kernel/src/index.ts` re-exports `./generated/requirements.js`. Nothing on the build path writes it: not
`pnpm install`, not `pnpm build`, `pnpm dev` or `pnpm package`, and not `pnpm worktree:new`, whose `pnpm preflight`
does not check for it. In a tree where neither the gate nor a test run has happened yet, `pnpm build` fails at once:

```
[UNRESOLVED_IMPORT] Could not resolve './generated/requirements.js' in ../../packages/kernel/src/index.ts
```

The message names the missing module, not the command that writes it. After `pnpm symbols` the same `pnpm build`
succeeds. A comment in `apps/desktop/scripts/lib/environment-facts.mjs` says the file "is rewritten by `pnpm symbols`
before every build and every test collection", which holds for the test collection and not for the build.

Found 2026-10-21 on Windows 11 ARM64, Node 24.11.0, in a worktree fresh from `pnpm worktree:new` at `7fa88ca1`, while
writing the root `README.md`. The README lists `pnpm symbols` before `pnpm dev` and `pnpm build` for this reason. Not
repaired.

## Specs

None in `docs/spec/`. ADR-0056 makes the artifact "a build input, regenerated by the test session before collection, so
the build and the test runner share one generator", and names nothing that regenerates it for a build that no test
session preceded.

## Relevant files

- `.gitignore` — `packages/kernel/src/generated/` is not committed.
- `packages/kernel/src/index.ts` — line 6, the re-export of `./generated/requirements.js`.
- `tools/symbol-artifact/generate.mjs` — the generator behind `pnpm symbols`; `tools/symbol-artifact/global-setup.ts`
  runs it before a test collection.
- `apps/desktop/scripts/preflight.mjs` — checks Node, Git, Electron, the build and the bundle, and not the generated
  symbols.
- `apps/desktop/scripts/lib/environment-facts.mjs` — the comment that says the build regenerates the file.
- `docs/architecture/adr/0056-the-build-toolchain.md` — the build-input bullet.

## Repaired — 2026-10-31

The build writes the artifact when it is absent, with the generator the test session runs. `tools/symbol-artifact/ensure.mjs`
is a Vite plugin at `buildStart`, carried by all three sections of `apps/desktop/electron.vite.config.ts`, so `pnpm build`,
`pnpm dev` and `pnpm package`'s own `electron-vite build` all reach it. It runs `generate.mjs` as a child process, as
`global-setup.ts` does, so there is still one generator. It runs only when the file does not exist. Keeping the file
current stays with `pnpm symbols` and the test session, as ADR-0056 has it. Every build pays one `existsSync`; a tree pays
one generator run (about 0.2 s) once. A generation that fails, or exits 0 and writes nothing, fails the build. The message
names the file and `pnpm symbols`, beside the generator's own error. The `environment-facts.mjs` comment and the README's
setup lines now say what the tree does.

Linux x86_64, Node 26.12.1, on `c583e1bc`. `rm -rf packages/kernel/src/generated && pnpm build`: exit 1 with the
`UNRESOLVED_IMPORT` above before the change, exit 0 after, with one generator line across the three sections. The same
with `packages/kernel/src` made read-only: exit 1 at `[plugin rotaris:symbol-artifact]`, naming the file and
`pnpm symbols` under the generator's `EACCES`. Regressions: `tools/symbol-artifact/ensure.test.ts` (absent → written;
present → the generator is not run; a failing or silent generator → the error) and `apps/desktop/electron.vite.config.test.ts`
(each section carries the plugin, pointed at the file `packages/kernel/src/index.ts` re-exports). Each goes red when its
part is reverted: the plugin taken out of one section, the existence check removed, or the throw swallowed.
`apps/desktop/scripts/preflight.mjs` still does not check for the file, and no longer needs to.
