# Request log

Every request the owner makes that could change what the product does, logged **when it is made** —
before it is classified, and before any code is written.

The log exists because the failure it prevents is silent: a request arrives in conversation, an agent
builds it, and the behaviour lands in the product with no identifier against it, invisible to
traceability and to the clean-room argument. A row here is cheap. Reconstructing one afterwards is
not possible.

**Declined and deferred requests stay.** A refusal with no record can be asked again in three weeks
and answered differently, and nobody can see that it happened. The reason is part of the row.

- Identifiers: `R-NNN`, contiguous from 1, never reused, and never renumbered **once the row has
  reached `main`**. A number two worktrees both took is settled at the merge, not afterwards: the row
  that landed first keeps it, the other takes the next free one and says in its own cell that it did.
- **Classification** is one of the five in [`README.md`](README.md)'s table: `covered`, `question`,
  `escalation`, `defect`, `directive`.
- **Disposition** names where it landed — a `PD`, a `REQ` it turned out to be covered by, an `OQ`, an
  `ESC`, or `declined` / `deferred` with the reason.
- A row is **appended and never rewritten**. A request that changes gets a new row citing the old one.
  What the rule protects is the *request* — the owner's words, the date, the classification, the
  disposition. Sorting the table is not rewriting it, and neither is the merge-time renumbering above,
  which moves an identifier and not one word of what was asked.

## Count

**Seventy-two requests, R-001 to R-072.** One row, one identifier, no gap — so the highest identifier is
the number of rows, and there is nothing here for a reader to tally.
[`tools/check-request-log.mjs`](../../tools/check-request-log.mjs) holds that as part of `pnpm lint`,
because a count written in prose is exactly what let seventeen rows sit under the word "Sixteen".

**The log has no allocator, and cannot cheaply have one.** An `R-NNN` is unique only against the
`main` the session that chose it last read, and this repository puts every change in a temporary
worktree — which is precisely the case where that is not the `main` the row lands on. It has happened
twice: two rows were numbered `R-016` on 2026-09-14 and **both merged**; two were numbered `R-018` the
next day and the second was caught by hand at the merge. Both are settled by the same rule — the row
that reaches `main` first keeps the number, the other takes the next free one and says so in its own
cell. `R-019` (the activity line) and `R-020` (the continue-run credential lease) are the two that
moved. The `R-016` pair is recorded as
