# `checkpoint-proof`

What this proof measures and re-verifies. The [proof registry](README.md) carries its area, prerequisites,
platforms, flags and neighbours; the script is [`apps/desktop/scripts/checkpoint-proof.mjs`](../../apps/desktop/scripts/checkpoint-proof.mjs).

The capture at iteration close through to the desktop restore (ADR-0039); since 2026-10-14 (fin45) its `restore` launch reads the preview field's computed face while the confirmation is up and fails one that is not the monospace token's (REQ-GIT-097, REQ-GIT-152; `docs/defects/fixed/the-restore-confirmations-preview-field-is-not-drawn-in-the-monospace-face.md`); since 2026-10-13 (N68) its `hook-capture` launch has a global `iteration_end` hook write a file and reads it in that iteration's checkpoint (REQ-HOOKS-082, POSIX hosts); the `live` launch's lock is probed dead the moment it returns (`lib/lock-holder.mjs`), so a lock that outlives the application fails there and is not blamed on the `repaired` step (`docs/defects/fixed/checkpoint-proofs-repaired-step-blames-the-repair-for-a-lock-its-live-launch-left-held.md`); since 2026-09-29 the `loaded-restore` launch restores a session still loaded after its run, once a second holder has taken its lock, and fails on a restore that writes under that holder (`docs/defects/fixed/a-write-through-a-loaded-sessions-writer-outside-a-run-claims-no-lock.md`)
