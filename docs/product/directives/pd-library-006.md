### PD-LIBRARY-006 — while the Library's query is non-empty each tab shows how many of its rows match

While the Library's search field (REQ-LIBRARY-103) holds a non-empty query, each of the three tabs MUST show, beside its label, the exact number of rows on that tab the query matches under REQ-LIBRARY-104: for "Prompts", the stash and history rows; for "Artifacts", the session-artifact rows; for "Improvement proposals", the improvement-artifact rows matched on their id (REQ-LIBRARY-166) together with the proposal rows, counted independent of any artifact selection, since that selection is not the query. The figure MUST be exact, `0` included, and MUST NOT be abbreviated; it is a quantity, set in the design language's monospaced figure, carrying no colour, fill or state of its own. While the query is empty, no count MUST be shown. The tab's visible label and its accessible name MUST remain exactly the strings REQ-LIBRARY-103 fixes; the count MUST reach assistive technology as the tab's accessible description, MUST NOT be part of its accessible name, and MUST NOT be a live region. The counts MUST follow REQ-LIBRARY-105: they change with the settled burst and never disturb text being typed in the search field.

**Why, and what it costs.** REQ-LIBRARY-104 makes one query filter all three tabs simultaneously, but nothing in the record shows that filtering on a tab that is not selected: an operator who finds nothing on Prompts concludes the thing is absent while Artifacts holds it, and the only way to learn otherwise is to switch tabs one by one. Raised as [OQ-534](../../archive/architecture/open-questions/71-spikes-and-later-questions-38-continued-2.md#oq-534). A count beside each label is that filtering made observable before switching, and no requirement asks for it — REQ-LIBRARY-103 fixes a tab's label, accessible name, order and stable name and nothing else a tab shows — so it enters as a directive beside REQ-LIBRARY-104 rather than as a reading. The figure stays outside the label and outside the accessible name so REQ-LIBRARY-103's strings are untouched and a reader still hears the tab by its fixed name; it is exact and never abbreviated because a quantity on a narrow strip must be read, not estimated; it is shown only while a query applies because with an empty query it would be a row total the Library never promised. The cost is one more figure on the tab strip at REQ-SHELL-022's minimum width, three counts computed per settled burst, a count option on the shared tab control, and a count that reaches assistive technology as a description only, whose perception is unmeasured and reopens the question. No requirement is displaced: REQ-LIBRARY-103, REQ-LIBRARY-104 and REQ-LIBRARY-105 govern in full, and the directive adds the figure beside them.

> **Extends:** REQ-LIBRARY-104
