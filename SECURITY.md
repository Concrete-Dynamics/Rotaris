# Security Policy

Concrete Dynamics UG (haftungsbeschränkt) maintains Rotaris and Rotaris Cloud. This
document is our coordinated vulnerability disclosure policy and names the single point
of contact for security matters, as required by Regulation (EU) 2024/2847.

## Reporting a vulnerability

Email **security@concrete-dynamics.com**. Do not open a public issue, and do not
disclose the report until we have agreed a date with you.

Tell us what you can:

- what the flaw is and where it lives — component, version, platform
- how to reproduce it, ideally as a minimal case
- what an attacker gains
- how you would like to be credited, or that you would rather not be

If the report contains data that is not yours to share, redact it first. We do not need
your customer's source code to understand a path traversal.

## What happens next

| Step | When |
| --- | --- |
| We confirm receipt | within 72 hours |
| We tell you our assessment — severity, whether we can reproduce it, our plan | within 7 days |
| We ship a fix | depends on severity; critical issues take priority over everything else |
| We publish an advisory and credit you | with the fix, or 90 days after your report, whichever comes first |

If we cannot meet a date, we say so and give you a new one rather than going quiet. If
you disagree with our assessment, say so — we would rather argue about severity than
read about it later.

## Scope

**In scope:** the Rotaris desktop application, the CLI and TUI surfaces, `rotaris-core`,
the release and update mechanism, and the Rotaris Cloud service at `rotaris.ai`.

**Out of scope:**

- **Rotaris running commands and editing files.** That is what the product does. A
  report that an approved tool call modified a file is not a vulnerability. A report
  that a tool call bypassed the permission policy, or that a permission decision could
  be forged, very much is.
- Vulnerabilities in a model provider's service. Report those to that provider.
- Findings that require an attacker who already has the ability to run code as the user,
  unless Rotaris is what grants that ability.
- Reports produced by a scanner without a working proof of concept.
- Social engineering, physical attacks, and denial of service by volume.

## Safe harbour

If you follow this policy — you act in good faith, you stay within the scope above, you
do not access, modify, or destroy data that is not yours, you do not degrade the service
for others, and you give us the time this policy sets out — we will not pursue legal
action against you, and we will say so in writing to anyone who asks.

We do not currently run a paid bounty programme.

## Supported versions

Security fixes go into the latest release. We do not backport to older versions.
[TO BE DECLARED before market launch: the support period we commit to, per Art. 13(8)
CRA — the recommendation is five years from the release of each version.]

## Release integrity

Every release publishes SHA-256 checksums for its artifacts. The built-in updater
refuses to install a download whose checksum does not match, and refuses outright when a
release publishes no checksum file. Verify downloads you obtain by other means against
the published checksums. [Code signing is planned; until it ships, checksums are the
only integrity guarantee we offer.]

## Third-party components

Each release ships `THIRD-PARTY-LICENSES.txt`, the complete inventory of bundled
components and their licences, generated by `packaging/third_party_licences.py`.
