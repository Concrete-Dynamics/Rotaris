# Conversation, Composer, and Transcript — 10. Desktop Tool, Thinking, and Grouped Rows

Part 4 of 7 of [domain 03](../03-conversation-composer-transcript.md), which indexes every part. Defines REQ-CHAT-060 – REQ-CHAT-084.

### 10. Desktop Tool, Thinking, and Grouped Rows

- **REQ-CHAT-060** — A tool row MUST render a monospace header `▸ toolname args`, with the chevron and tool name in the tool accent colour and the outcome appended on the same line: `ok · <seconds>s`, the duration carrying one decimal place (for example `ok · 3.2s`), when the call succeeded; `failed` when it did not; and a pulsing `◉ running…` while it is still in flight. A row whose tool status is `blocked` MUST render `blocked · <seconds>s` in the theme's `fail` state text colour, and where the reason the call was blocked is known that reason MUST be reachable from the row — through the expansion of REQ-CHAT-061 and through the row's accessible description — so a blocked call is never mistaken for one that ran and failed. A row persisted with a ✓, ✗, or ! glyph already written into its text MUST render without that glyph, so the outcome is stated exactly once. The tool status vocabulary is closed to the four values `running`, `ok`, `failed`, and `blocked` named in REQ-CHAT-046 and fixed by REQ-MONITOR-105; there is no fifth value and no fallback that draws an unrecognized marker as its own literal text. A row carrying no status renders no outcome (REQ-CHAT-049), and a value outside the four MUST be treated as `failed` rather than displayed.
- **REQ-CHAT-061** — Clicking a tool row's header MUST expand it into a card that shows the **untruncated** call input and result, each introduced by a small caption in capitals reading `INPUT` and `OUTPUT` respectively. A collapsed tool row shows instead a single dimmed preview line introduced by `⤷`. A tool row with nothing extra to reveal MUST be non-interactive.

  > responses by default, with a toggle to inspect the raw untruncated JSON.

  > chevron alone. Every other stop, and every row the reader opens, keep the preview and the untruncated card exactly as

- **REQ-CHAT-062** — Thinking rows MUST summarize as `▸ reasoning · <N>s · ~<T> tok`; while streaming they render `◉ reasoning… <N>s · ~<T> tok` with both numbers counting upward, where the token figure is the streamed character count divided by 4. They are collapsible by click. A live thinking row MUST stop presenting as live after 3600 seconds without completion.
  > **Narrowed by [`PD-CHAT-004`](../../product/directives/pd-chat-004.md#pd-chat-004), 2026-09-15; revised 2026-09-16.** A thinking row
  > drawn **as a row** still summarizes exactly as above, and does so whenever `display/showReasoning`
  > is on or the run it would join holds fewer than two rows. Inside an activity line it is a member:
  > the line states the segment's summed seconds and summed token figure by this requirement's own
  > arithmetic, and expanding the line reveals the row drawn as above. The 3600-second cutoff is
  > untouched.
- **REQ-CHAT-063** — While any row is live — a running tool, verifier, or group, or reasoning that is still streaming and unstamped — the desktop transcript MUST refresh those rows at least once every **1000 ms**, and at least once every **250 ms** while a terminal stream is live, so their elapsed times advance and their spinners animate. Every live row MUST keep advancing regardless of how many rows sit below it. When no row is live, nothing in the transcript may animate or repaint on a timer. Timed refreshes MUST NOT move the reader's scroll position, change any row's expansion state, or make rows that are not live flicker or reflow.
- **REQ-CHAT-064** — Folding rule: a run of at least **2** consecutive tool rows that belong to the same agent and whose tool names map to the same family MUST collapse into a single group header row labelled with that family's activity word. Family membership: read/read_file/list_dir/list_files/glob/view → "reading"; edit/edit_file/write/write_file/create_file/str_replace/str_replace_editor/apply_patch → "editing"; grep/grep_search/search/codebase_search/web_search → "searching"; bash/execute/execute_bash/terminal/run_command → "running". A tool name outside those lists forms a family of its own, labelled with that tool name, so it folds only with consecutive calls to the same tool. Any intervening message, thinking, different-agent, or different-family row ends the run and prevents rows on either side of it from folding together.
  > **Narrowed by [`PD-CHAT-004`](../../product/directives/pd-chat-004.md#pd-chat-004), 2026-09-15; revised 2026-09-16.** The family
  > membership table above, the two-row floor and the rule that an unlisted tool name forms a family of
  > its own are **untouched and still govern** — the directive reads them. What it narrows is the **run
  > boundary and the header's label**: a run is bounded by the agent and the category, so a change of
  > family and an intervening thinking row no longer end it, and the header names every segment of the
  > run rather than one family word. A message row, a different-agent row and REQ-CHAT-066's exempt
  > rows still end a run exactly as above.
- **REQ-CHAT-065** — A group header MUST carry the number of members with each outcome (ok, failed, blocked, running), the sum of the members' durations, the earliest member start time, and — while a member is in flight — that call's text. It MUST also carry the searchable text of its members, capped at **2000** characters, so REQ-CHAT-074 can match inside a collapsed group. The header MUST take its colour from the most severe member outcome, and while any member is running its duration MUST count upward. Expanding a group MUST keep the header on screen and reveal its members beneath it. Copying a group, and the group's accessible description, MUST both yield a readable summary that starts with "<family> ×N" and continues with the per-outcome counts (for example "reading ×4 · 3 ok · 1 failed"), and MUST NOT emit raw tool input or output. The header's colour is chosen by this severity ordering, highest first: `failed`, then `blocked`, then `running`, then `ok` — so one failed member colours the whole group as failed however many members succeeded, a group with no failure but a blocked member reads as blocked, and a group is only ever coloured as running or as ok when nothing in it went wrong.
  > **Narrowed by [`PD-CHAT-004`](../../product/directives/pd-chat-004.md#pd-chat-004), 2026-09-15; revised 2026-09-16.** The per-outcome
  > counts, the earliest start, the in-flight call's text, the 2000-character searchable blob, the
  > severity ordering and "expanding keeps the header on screen and reveals its members beneath it" are
  > **untouched**. Two clauses are narrowed where the directive governs. The header's figure is the run's
  > **elapsed span** rather than the sum of the members' durations, because a run crossing families and
  > reasoning is read for how long the agent has been at it. And the summary is **per segment** —
  > segments separated by `, `, facts inside one by ` · ` — which leaves this requirement's own example,
  > `reading ×4 · 3 ok · 1 failed`, exactly as written for a run of one family and no reasoning. The
  > severity is taken over the **tool** members only, so a reasoning-only run is never coloured failed.
  > **`PD-CHAT-004` revision 3, 2026-09-15**, narrows one clause further. The severity ordering above is
  > still **untouched** — the activity line computes it, publishes it, and states it in the copy summary
  > and the accessible description. What the revision narrows is the one clause that turns it into a
  > colour: the line does **not** take one colour from the most severe member outcome. The fail colour is
  > drawn on the `N failed` and `N blocked` counts inside the segment that holds them, and nothing else
  > on the line changes hue. A tool row drawn as its own row is unaffected and REQ-CHAT-060's colouring
  > governs it in full. The text above states the behavioural target and is kept for that reason.
- **REQ-CHAT-066** — The structured-questions tool row MUST never fold into a group, and an unsettled live terminal row MUST never fold into a group (its live preview must stay visible). Incremental updates to grouped transcripts MUST remain incremental, refusing (and falling back to a full refresh) only when the update and the view describe different transcripts.
- **REQ-CHAT-067** — A persisted display setting MUST auto-collapse all but the most recent tool-call/result pair (the last two tool rows; fewer than two → none collapse) to name-plus-chevron; it defaults **off**; per-row manual expansion overrides it; question rows and live terminal rows are exempt; toggling takes effect immediately. The tool-grouping display setting defaults **on**. Both of these are desktop preferences and are stored in the desktop preference store (REQ-CONFIG-405), not in the YAML configuration surface.

  > line**: with it off no run is formed and every row draws as its own category states. Auto-collapse
  > acts on tool rows drawn as rows — a run of one, and every tool row while grouping is off. The members
  > revealed beneath an expanded line are **exempt**, as a folded group's members already were before this
  > directive: a reader who opened the run asked to see its steps, and taking them to name-plus-chevron in
  > the same gesture would undo what the expansion was for.

  > the grouping setting is on at Compact, Brief and Standard and off at Detailed and Expanded, and auto-collapse is

  > **stops** of one slider, stored as one integer (`display/toolVerbosity`) rather than two booleans: **Brief** is this

  > which collapses the most recent pair too; **Detailed** and **Expanded** are this requirement's grouping switch

- **REQ-CHAT-166** — Tool-row content MUST be governed by persisted settings offered in the settings surface and mirrored into the catalogue by REQ-CHAT-028: whether tool results are shown, defaulting **shown**; whether tool inputs are shown, defaulting **shown**; and a rendered-line cap for each, defaulting to **10** lines for results and **2** for inputs, offered as the values 1, 2, 5, 10, 20, 50, and unlimited. These four are workspace configuration, written to and read back from the `display` section of the workspace `agents.yaml` (REQ-CONFIG-172, REQ-CONFIG-175). The settings surface that offers them is the Display category controls of REQ-CONFIG-472, which this requirement relies on for where the four controls live and for the write path that puts their values into that section. A cap MUST affect only what is drawn: the session record MUST retain the full text (REQ-CHAT-046), so raising a cap or reopening the session shows the rest without re-running anything. Truncation MUST be marked in the drawn text, stating that the result or the input was cut short and how many further lines exist. Expanding a row per REQ-CHAT-061 MUST show the untruncated value whatever these settings say, and a change to any of them MUST take effect immediately on the rows already on screen.
- **REQ-CHAT-167** — A persisted desktop preference MUST control whether reasoning bodies are shown, defaulting **off** so that reasoning rows summarize per REQ-CHAT-062 and reveal nothing until asked. It is global to the transcript — changing it changes every reasoning row at once — and MUST be reachable both from the settings surface and from the command palette, and therefore as a slash command (REQ-CHAT-028). Toggling MUST report the new state, MUST take effect immediately on the rows already on screen, and MUST NOT move the reader's position (REQ-CHAT-071). A row the user has expanded or collapsed by hand keeps the state the user gave it, overriding the preference for that row until its expansion state is reset (REQ-CHAT-059). The preference is stored in the desktop preference store under the registered key `display/showReasoning` (REQ-SHELL-006, which registers the key set of that store), is written user-wide like every desktop preference (REQ-CONFIG-405), and is not part of the YAML configuration surface.

  > Settings › Display › Transcript's second control, after [`PD-CHAT-010`](../../product/directives/pd-chat-010.md#pd-chat-010)'s
  > slider, written the moment it moves and not undone by Discard. *(Revision 2 of the directive replaced the three-switch
  > heading this note first described; the switch's own key, hint and commit policy are unchanged.)*
- **REQ-CHAT-175** — A tool row MUST carry a one-line description of what the call does, derived from the tool's name and the arguments the row records, and MUST draw that line as the row's header text in transcript history. The derivation MUST be a pure, deterministic function of those two facts — the same tool name and the same arguments always yield the same line — and MUST make no model call, read no clock, hold no state and change nothing about the call: not its arguments, not its outcome, not its permission decision and not the row the store keeps, and no guard or policy decision may read it. The line MUST state the action and its most telling argument where one exists, in the shape "Runs npm test", "Reads src/app.ts", "Searches for release.yml"; it MUST be one line, with every run of whitespace inside an argument collapsed to a single space, and MUST be cut at **120** code points with a trailing `…` where it is longer. A tool the build derives no line for, and a call whose arguments are absent or unreadable, MUST draw the tool's own name, so no row is drawn with an empty header; a row that carries no tool name at all falls back to the text it recorded.
- **REQ-CHAT-176** — The arguments the description is derived from MUST pass through the same redaction pass the row's output passes through (REQ-TOOLS-171) before the line is drawn, and the line MUST be cut only after that masking, so a credential carried in an argument — a bearer token, a secret-looking flag's value, a password inside a URL — never reaches the description. The derivation MUST hold no redaction rule of its own.
- **REQ-CHAT-177** — The description MUST be the header of a tool row at **every** stop of `display/toolVerbosity`, from **1** (Compact) through **5** (Expanded). The stop governs what else the row draws — whether a run folds into an activity line, whether the `⤷` preview is drawn, whether the card is already open — and MUST NOT hide the description, shorten it to the tool's name, or replace it with the stop's own wording on a tool row the stop draws; a stop that does any of those is a defect of that stop. A run the stop folds is [`PD-CHAT-004`](../../product/directives/pd-chat-004.md#pd-chat-004)'s activity line and draws no tool row; the members' descriptions are drawn when the run is opened. While the slider is recorded and not built ([`PD-CHAT-010`](../../product/directives/pd-chat-010.md#pd-chat-010)) the description is drawn unconditionally, so the five stops cannot disagree about it.
- **REQ-CHAT-178** — The description MUST be the first text of the tool-row header's accessible name, so a screen reader announces what the call does before the outcome REQ-CHAT-060 appends to the same line. The header MUST NOT carry an accessible name that omits the description or that is the tool's name alone.
- **REQ-CHAT-068** — Selecting a child agent MUST place a collapsible delegation-context header row above that agent's transcript; selecting a root agent MUST NOT produce one. Expanded, the row MUST show the task name, the persona, the task category, whether the task runs in the background or blocks its parent, the full task text, the task's dependencies, and the context inherited from the parent. Collapsed, it MUST show a single summary line conveying exactly three facts — the child agent's name, its persona, and its task, the task compacted to at most **110** characters with an ellipsis where it is cut — with the arrangement, separators, and any leading marker left to the implementation. A delegation payload whose fields are missing or unreadable MUST still produce a row showing the fields that could be read, and MUST NOT surface an error to the user or prevent the rest of the transcript from rendering; a summary line that cannot name all three facts MUST name those it can rather than showing a placeholder for the rest.
  > **Extended by [`PD-CHAT-005`](../../product/directives/pd-chat-005.md#pd-chat-005), 2026-09-16.** The delegation
  > header above is unchanged and stays the place the child's task is read in full. The directive
  > makes the same parent/child relation visible without selecting the child, by indenting that

- **REQ-CHAT-069** — A transcript scope toggle MUST switch between "All activity" and "This task". Filtering keeps rows of kinds user, system, question, approval, and verifier (run-owned) plus the selected agent's rows; verifier rows MUST never be filtered out per agent. The toggle MUST name the agent "This task" refers to and show that agent's state and its live elapsed wall-clock time (REQ-MONITOR-111), so the reader can tell whose output is being shown without leaving the transcript. With no agent selected, "This task" MUST be unavailable with that as its stated reason rather than filtering the transcript to nothing.
  > **Extended by [`PD-CHAT-005`](../../product/directives/pd-chat-005.md#pd-chat-005), 2026-09-16.** The scope

### 11. Desktop Transcript Scrolling, Tail-Follow, and Search

- **REQ-CHAT-070** — The transcript MUST be in exactly one of two states, following the tail or not, and MUST be following whenever its scrollbar rests at its maximum. While following, the transcript MUST show a border treatment that is absent while not following, and its accessible description MUST state which of the two states is current, so the distinction is available without seeing the border. Only movement the reader causes may change the state; keyboard scrolling re-derives it, while scrolls the application performs itself — pinning to the bottom, restoring an anchor, jumping to a search match — MUST leave it unchanged. After the set of rows changes, the reader's position MUST be restored by locating the anchored row again, never by re-applying a stored pixel offset. The accessible description MUST convey which of the two states is current and, while not following, that new output is arriving out of view; its wording is left to the implementation, provided the two states are never described by the same text.
- **REQ-CHAT-071** — Before rows move, the view MUST record the identity and viewport offset of the top visible row and restore that anchor after geometry settles, so text does not jump under the reader when heights above the viewport change.
- **REQ-CHAT-072** — When rows are appended while the reader is not following the tail, a hidden "New output" toolbar button MUST appear labeled "N new update(s)", counted in **displayed** rows (grouping-aware). Clicking it re-enables tail-follow and hides itself; resuming follow by scrolling also hides it.
- **REQ-CHAT-073** — With zero transcript rows the transcript area MUST show an empty state ("No transcript yet" / "Describe the outcome you want. Rotaris will show agent activity and results here.") and the Clear action MUST be disabled.
- **REQ-CHAT-074** — Transcript search: opened by toolbar button or Ctrl+F as an inline panel with input placeholder "Search transcript…", a count label, and Previous/Next/Close. Matching is case-folded substring over role + text + tool name + detail (for group headers: role + family + the capped member blob, so a hit inside a collapsed group lands on its visible header), indexed against **displayed** rows. The count shows "X of Y" or "0 results". Enter in the field means Next. Navigation wraps in both directions. Showing a match disables tail-follow, selects the row, scrolls it to center, and paints a match highlight. Matches recompute automatically whenever rows change while the panel is open with a query. Closing the panel refocuses the composer.

### 12. Desktop Copy and Row Interaction

- **REQ-CHAT-075** — Every row's context menu MUST offer "Copy message" (the row text; for groups, the group summary). Tool rows MUST additionally offer "Copy tool input" and "Copy tool output", each copying the untruncated value; either entry is greyed out when its value is empty, and neither entry appears at all on a row that is not a tool row. The platform-standard Copy shortcut (Ctrl+C) MUST copy the selected message. A copy the platform refuses MUST be reported as a failure naming what could not be copied and MUST NOT be reported as a success; a copy that succeeds MUST be acknowledged. Transcript text MUST be selectable with the pointer, selecting exactly the characters the pointer covers, in every row category including rows whose body is rendered Markdown.
- **REQ-CHAT-076** — Click routing: clicking a group header toggles the group; clicking a reasoning/tool/delegation header toggles that one row, re-measuring only it; clicking a live terminal preview requests the terminal pop-out for that stream; clicking a question row opens the question stepper; clicking an approval row opens the approval dialog; `http(s)` links open in the system browser. A bare `http(s)` URL appearing in any row's text — not only one written as a Markdown link — MUST be activatable in the same way, with trailing punctuation excluded from the link target. Opening MUST be acknowledged and a failure to open MUST be reported rather than passing silently.
- **REQ-CHAT-077** — Full keyboard navigation MUST work in the transcript: arrow keys, PageUp/PageDown, Home/End all move the current row; selection is supported; the hovered row receives hover styling.

### 13. Desktop Manual Context Compression

- **REQ-CHAT-078** — A "Compress context" control in the run header (accessible description "Manually compress context for all active agents") MUST be enabled only while a run is running and locally owned. When disabled it MUST state why, using the same reason text as the other run controls — pause, cancel, and the run header's own model and reasoning selectors, which change the live run and are distinct from the composer chips of REQ-CHAT-006 and REQ-CHAT-009: "Recover this session before using run controls." when the session needs recovery, "Continue the paused run before using run controls." while paused, "Run controls are unavailable while <run-state label, lowercased>" while otherwise busy, and "Start or continue a run to enable run controls." when no run is under way.
- **REQ-CHAT-079** — Activating it when nothing can be compressed (no run machinery or no active agent conversations) MUST toast "No active agent contexts are available to compress.". Otherwise the button disables and relabels "Compressing…" and a toast reads "Compressing active agent contexts…".
- **REQ-CHAT-080** — On completion the button label is restored and either a toast reads "Compressed context for N active agent(s)." or a persistent notice "Context compression incomplete" is raised with per-agent error details. All active conversations compress concurrently.
- **REQ-CHAT-081** — Manual compression MUST compress unconditionally: it never consults the automatic-compression threshold configuration.

### 14. Desktop Transcript Clearing

- **REQ-CHAT-082** — "Clear transcript" (toolbar, accessible description "Permanently remove transcript messages from the loaded session") and `/clear` MUST invoke the same flow. With an empty transcript the flow only toasts "Transcript is already empty.".
- **REQ-CHAT-083** — Otherwise a confirmation dialog MUST ask "Clear transcript?" with body "This removes the visible conversation from the loaded session. Agent state, artifacts, and Git changes remain." and impact statement "Transcript messages cannot be restored after the session snapshot is saved."; the confirm action is labeled "Clear transcript". Declining does nothing.
- **REQ-CHAT-084** — Confirmed clearing routes by run state: with an active local run, the live run's recorded transcript is cleared such that the run's own next write cannot resurrect old rows; with a non-running named session, the persisted snapshot is cleared atomically and the view re-projected. Failures raise the persistent notice "Could not clear transcript" or toast "Transcript is busy and could not be cleared.". Success clears the visible transcript and toasts "Transcript cleared. Session artifacts and agent state were kept.".
