### PD-STARTUP-011 — a run directory carries the application log, and a window whose default base cannot be created writes under the per-user data directory

*Revision 2 (2026-11-04, [OQ-541](../../archive/architecture/open-questions/71-spikes-and-later-questions-38-continued-5.md#oq-541)) — **the window that takes the per-user base**, below, and the title with it. Revision 1 (2026-11-04, [OQ-480](../../archive/architecture/open-questions/71-spikes-and-later-questions-38-continued-4.md#oq-480)) is quoted where it is replaced, never deleted. A changed directive takes a revision and never a new number ([`README.md`](../README.md)).*

REQ-STARTUP-132's written artifacts SHALL further include `app-log-NN.jsonl`: one record per line the application log records, after PD-MONITOR-002's threshold and REQ-TOOLS-171's redaction pass, as `{at, level, source, message}`, bounded as REQ-STARTUP-133 bounds every JSON-lines stream, read as REQ-STARTUP-138 reads one, and named in the manifest's `captured` list so a reader knows an absent stream is unbuilt and not lost. The stream SHALL carry the instance's whole log for as long as its window lives — every window's lines and main's own, unfiltered by window — and SHALL begin at the capture's start: lines recorded before it are not carried, because REQ-STARTUP-130 permits no work at `off`. REQ-STARTUP-134's ban on session content binds the stream as written and by kind: a folder path, a provider's error text and a child process's own diagnostic lines are permitted; no line at any level SHALL quote transcript or prompt text, model output, a tool's result, a file's contents or a credential, whoever produced the text, and a writer that would otherwise quote one SHALL write its source, kind and byte length instead. The obligation sits on each writer of the application log, held by a test beside it, and the stream SHALL NOT be filtered a second time. The diagnostics card of REQ-SHELL-163 SHALL say in words that a run directory holds this application's log for every open window, that the log includes folder paths and error messages, and that it holds no conversation, model output or file contents.

**The base (revision 2).** A main window whose `diagnostics/outputDir` is unset SHALL take `<workspace>/.rotaris/diagnostics/rotaris` as its base only when the folder it is built for is an existing directory at the moment the window is built and its run directory can be created there (REQ-STARTUP-131); in every other case — a window built with no folder, or for a path that is a regular file, missing, unreachable or unwritable — it SHALL take `<per-user data directory>/diagnostics/rotaris` (REQ-STARTUP-145, whose machine-local clause it inherits), and SHALL create nothing under a path that is not an existing directory. The base is decided inside the window's build, is fixed then, and SHALL NOT be moved by what the window's open then does or by a workspace opened later. A window SHALL open with diagnostics inactive only where the per-user base itself cannot be created, and the card of REQ-SHELL-163 SHALL then name that base and the cause, and the workspace default that failed before it where one did; a chosen `diagnostics/outputDir` that cannot be written SHALL leave the window inactive as REQ-STARTUP-131 says and SHALL never be redirected. The manifest's `outputBase` SHALL name the base in force, and where the per-user base was taken in place of a workspace default the capture's first recorded line SHALL name that base and the cause. The diagnostics card SHALL show the base in force as the folder in force and, where the fallback was taken, SHALL say in words that the workspace's own folder could not be written and name the cause; at `off` nothing is checked and nothing is created (REQ-STARTUP-130), and the card shows the workspace default. Everything else of revision 1 — the `app-log-NN.jsonl` stream added to REQ-STARTUP-132's written artifacts, its bounds, the content rule by kind at each writer, and the card's three sentences — governs unchanged.

> **Revision 1 said, and no longer governs:** "A window that holds no workspace and whose `diagnostics/outputDir` is unset SHALL take `<per-user data directory>/diagnostics/rotaris` (REQ-STARTUP-145, whose machine-local clause it inherits) as its base, fixed when the window is built and unmoved by a workspace opened later; REQ-STARTUP-131's inactive case stays the one it names, that base itself being unwritable. The diagnostics card of REQ-SHELL-163 SHALL show that folder as the one in force" — the card's three sentences that followed are unchanged.

**Why revision 2, and what it costs.** Revision 1 gave the per-user base to "a window that holds no workspace", for "the welcome window and a refused or failed open, the launches where a fault leaves no other trace"; built and measured on 2026-11-04, every main window is built for a folder and its capture fixed then, so no launch reached that base and a launch given a regular file had its open refused and its capture inactive with `ENOTDIR`, keeping no log — the one incident the directive was minted for, and REQ-STARTUP-131's "SHALL never silently disable itself" departed from again. Deciding at build keeps what revision 1, REQ-STARTUP-129 and REQ-SHELL-163 fix — a base set when the window is built, a choice reaching only later windows, a stream that begins at the capture's start with no buffer before it (REQ-STARTUP-130) — where a capture that waited for the open to settle would lose the refusal and warning lines it exists to keep. The existing-directory check is there because the run directory is created recursively, and a missing workspace path would otherwise gain a `.rotaris/diagnostics/rotaris` tree under a folder whose open is then refused with the promise that nothing was written to it; it is the check startup already makes for a remembered folder. Only the default is redirected: a folder the user chose is their choice under REQ-STARTUP-129, and overriding it would silently move what they asked for. What it costs: a log can land in a per-user folder the user may not look in, which is why the card and the first line say so and the card's open-folder control reaches it; two incidents on one workspace can land in two places when its folder is reachable one day and not the next; the per-user folder gathers paths and error text from workspaces whose own folder could not hold them, with nothing removing old run directories (revision 1's cost, widened); an existing directory whose open is refused for another reason — held elsewhere, untrusted, a store failure — still writes under its own `.rotaris/`, readable but not where "a refused or failed open" might be looked for, because the rule decides by a check at build and not by the open's outcome; a folder removed between the check and the create ends under the per-user base rather than inactive; at `off` the card's folder is the workspace default unchecked, so it can differ from the base a `light` window built next would take; and one more dependency in `DiagnosticsCapturesDeps`. Given up on purpose: a capture that starts after the open, and any redirection of a chosen folder. Raised by [OQ-541](../../archive/architecture/open-questions/71-spikes-and-later-questions-38-continued-5.md#oq-541), building revision 1's first execution.

**Why revision 1, and what it costs.** A packaged Windows build writes its application log to a standard output nobody reads (`docs/architecture/hardening/02-the-findings.md` §3.4), and REQ-SHELL-163's card is the one switch a user has to keep a log they can read after an incident; REQ-STARTUP-132 enumerates a closed set the stream is not in, and REQ-STARTUP-131 names no base for a window with no workspace — the welcome window and a refused or failed open, the launches where a fault leaves no other trace — so the build's inactive window departed from its "SHALL never silently disable itself" either way. The content rule is applied by kind, not by provenance, because reducing every forwarded line to a length would make the run-directory copy weaker than the standard output in exactly the incident it exists for; the cost is that the guarantee rests on each writer and its test, and a third-party tool server's standard error, forwarded at `debug` when `ROTARIS_APP_LOG_LEVEL` admits it, is recorded as that process wrote it. What else it costs: a run directory under workspace A holds paths and error text from workspace B, kept out of every capture by REQ-GIT-003 and said on the card, but shared with whoever A's `.rotaris/` is shared with; a per-user folder the user may not look in, reachable through the card's open-folder control, where nothing removes old run directories, each stream bounded at 32 MiB but their number unbounded; and three back-pointers, while the metric and span streams, the snapshots and the summaries stay owed. Given up on purpose: a per-window attribution of lines, which the run host's lines cannot keep and which would promise a scope REQ-STARTUP-134 does not ask for; and a buffer of lines before the first window, which REQ-STARTUP-130 forbids. Raised by [OQ-480](../../archive/architecture/open-questions/71-spikes-and-later-questions-38-continued-4.md#oq-480).

Every main window is built for a folder and its capture is fixed then, so no launch reaches the per-user base, and the refused open this directive's reasons name keeps no log: raised as [OQ-541](../../archive/architecture/open-questions/71-spikes-and-later-questions-38-continued-5.md#oq-541), the build proceeding as ruled. The card, driven to Settings › About in the refused-file window, showed the three sentences, the folder in force and the inactive reason.

Read as permitted by kind and left as written: a hook's output in its failure warning (REQ-HOOKS' warning text, a child process's own lines), a provider's error text, and the verification-only capture seams' DOM reads, which a packaged build does not carry. *Corrected by the bundle's review, the same day: this read "one writer quoted model output and now says its source, kind and length; the others held". The two run warnings now say `planNotDoneInLog`'s count and `model output from the coordinator's plan, <n> bytes, not quoted` (`stop-conditions.ts`), the refusal's warning `tool output from the delegate tool's refusal, <n> bytes, not quoted`; the iteration's record, the transcript's row and the tool's result keep the words, and the tails the live run's `plan-open` reading and `mission-proof` read are unchanged (`run/coordinator-plan.test.ts`, `run/run-pure.test.ts`, `children/children.test.ts`).*
