# `exit-trace-proof`

What this proof measures and re-verifies. The [proof registry](README.md) carries its area, prerequisites,
platforms, flags and neighbours; the script is [`apps/desktop/scripts/exit-trace-proof.mjs`](../../apps/desktop/scripts/exit-trace-proof.mjs).

The exit trace's crash handlers in the built app (PD-MONITOR-002; since 2026-10-13, fin42, N60): an orderly launch and quit writes its quit lines and no GONE line at `error`; a second launch's run host is killed with SIGKILL from outside (its pid read from main's `hello` line) and main writes `run host exited (9)` and `CHILD PROCESS GONE (Utility rotaris-run-host: killed, exit 9)` at `error`, then its renderer is crashed with SIGSEGV and main writes `RENDERER GONE (crashed, exit 11) for <URL>` at `error`, and the application's quit (`app.quit()`) then ends the process, exit 0, through the orderly path (the dead renderer's close guard cannot answer, so it allows; since fin45, OQ-298, the quit asks no guard at all), with `quit: exiting with status 0` and `main process exiting with status 0` (since 2026-10-14, fin43: until then the quit was held for good, `docs/archive/defects/a-main-window-whose-renderer-crashed-holds-the-applications-quit-forever.md`); since 2026-10-14 (fin44, `PD-SHELL-010`) two more launches stop the main window's renderer with SIGSTOP and end the process, exit 0, through the orderly path within 15 s with main's `warn` line naming the unanswered liveness probe — `hang` by the driver's quit and `hang-close` by the host's close (the driver's `closeWindow`, `BrowserWindow.close()`); until then both were held for good (`docs/archive/defects/a-main-window-whose-renderer-hangs-holds-the-applications-quit.md`); since 2026-10-14 (fin45, OQ-298, `PD-SHELL-009` revision 2) the quit from outside any window asks no close guard, so `hang`'s quit exits 0 well under the probe's 5 s bound with main's OQ-298 line and no PD-SHELL-010 `warn` line (`hang-close`, a person's close, stays PD-SHELL-010's measure), and two `unsaved` launches whose renderer guard never settles — `unsaved-quit` (the driver's quit) and `unsaved-sigterm` (SIGTERM to main) — each exit 0 through `quit: exiting with status 0` with no dialog and the workspace configuration file byte-identical; `unhandledRejection` and `uncaughtException` cannot be raised in main from outside and stay unmeasured

**How a utility process ends on its own** (since 2026-11-03, R-091, hardening §3.2 row 1; [ADR-0002 part 12](../architecture/adr/0002-process-topology/12-first-execution-2026-11-03-a-child-ends-on-its-own.md)): two `last-resort` launches raise a throw in the run host and a rejection in the workspace service that no request path catches (the seam `ROTARIS_CAPTURE_CHILD_FAULT`, compiled out of a packaged build), and each child writes ONE `error` line with the stack through main's log and exits 70, which main reads as its last-resort handler's, before the application quits 0; the `main-killed` launch kills main from outside and reads every utility process gone within `RUN_HOST_END_BOUND_MS` (2,000 ms), on Windows through held process handles that also give each exit code (69 is the child's own parent watch), and describes any survivor's threads and children ([the orphaned run host note](../defects/the-run-host-outlives-a-killed-main-on-windows-and-keeps-calling-the-model.md)).

**A child lost, or never ready** (since 2026-11-04, [OQ-462](../archive/architecture/open-questions/69-spikes-and-later-questions-36.md#oq-462)'s ruling, hardening §3.2 rows 2 and 3): the `crash` launch's killed run host raises ONE error notice "The run host stopped" with a dismiss, no action and the status and pid in its detail, written to the log once at `error`, a submit after it is refused with the composer's draft kept, and a `session.list` is refused `runHost.gone` at once; two `not-ready` launches start a run host, then a workspace service, that never answers its `hello` (the seam's `silent`): the window still paints, main ends the child at the 5 s bound with no unhandled rejection, the run host's miss raises "The run host did not start" and refuses a later request at once, the service's refuses its open with the transient "The project could not be opened" and no notice, and each quits 0.

**A window that throws while it is drawn** (since 2026-11-04, R-091, hardening §3.2 row 4): the `render-fault` launch makes a component in the main window throw through the renderer seam `window.__rotarisRenderFault` (`renderer/render-failure.tsx`, mounted under `__ROTARIS_SEAMS__`, so a packaged build carries none) and reads the error boundary's fallback drawn in place of the shell with its one action "Reload this window", ONE `error` line from main carrying the error and the component stack, the reload asked of main and the shell drawn again, and the persistent error notice "This window stopped drawing" whose detail carries the error and the stack; the application then quits 0.

**On Windows** (since 2026-10-20, the Windows ARM64 session's C4): Node there sends only SIGINT, SIGTERM, SIGKILL and 0,
the last three as `TerminateProcess` with exit 1, so the win32 branch expects `run host exited (1)` and `… killed, exit 1)`,
ends the renderer with `process.kill(pid)` (main writes `RENDERER GONE (killed, exit 1)`), hangs it with `NtSuspendProcess`,
and has `unsaved-sigterm` check the termination (exit 1, no quit line) in place of the orderly path. Run it on a quiet host:
under a parallel session's 100% CPU the main process was reaped more than 15 s after its last line, and the orderly control
failed on that alone ([`exit-trace-proof-expects-posix-signal-semantics-on-windows.md`](../archive/defects/exit-trace-proof-expects-posix-signal-semantics-on-windows.md)).
