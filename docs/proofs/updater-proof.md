# `updater-proof`

What this proof measures and re-verifies. The [proof registry](README.md) carries its area, prerequisites,
platforms, flags and neighbours; the script is [`apps/desktop/scripts/updater-proof.mjs`](../../apps/desktop/scripts/updater-proof.mjs).

The updater on the one path a development host can execute: a launch that is not a released artifact performs no check and issues no request (REQ-STARTUP-106/114/150) — the log's one `info` line, and a proxy sink every request of Chromium's stack would reach that records none for the feed and **none at all** from launch to first paint and quit (REQ-STARTUP-160, REQ-SHELL-005 — the spellchecker's dictionary download it once caught), with a net-log naming the URL of any connection it does record; and a second launch, started with both artifact variables set, whose one scripted `terminal` call finds neither in its shell's environment (REQ-STARTUP-147); the check, the download, the apply and the restart are unit-tested over fakes and their run against a real artifact is owed to the next Windows package (IC-3 — *corrected 2026-10-14: a Windows x64 host, deferred with the pipeline under R-071; IC-3 binds Linux and macOS artifacts*); so are, since 2026-10-14 (fin46, OQ-311), `Restart now`'s and the installer's `Update now` unsaved-settings guard — every main window asked Save/Discard/Cancel in turn, a Cancel starting nothing, the configuration file left as it was — which no launch on a development host reaches (its build is classified not updatable and answers `update.notApplied` before any guard), so it is unit-tested over fakes (`updater.test.ts`'s OQ-311 block, `main-windows.test.ts`'s `askUnsavedInTurn`, `renderer/guard-question.test.ts`) and its built-app run is owed to the Windows package;
